# 技能系统实施记录

日期：2026-08-10

状态：已实施（2026-08-12）

## 产品结果

- 独立技能位于 `runtime/skills/`。
- 插件技能只从插件 manifest 明确声明的目录加载。
- 两种来源使用同一套发现、YAML 解析、校验、索引和正文读取规则。
- Agent 的 system prompt 只包含技能 ID、名称和描述，正文按需读取。
- 修改文件后可通过技能工作区手动重载，无需重启。

## 来源与标识

- 独立技能使用目录名作为 ID。
- 插件技能使用插件 ID 与目录名组成的命名空间 ID。
- `SKILL.md` 的 frontmatter 必须提供与目录名一致的 `name` 和非空 `description`。
- 重复 ID、无效字段或缺失文件会形成明确错误，不注册为有效技能。

## 模块职责

### Skill Loader

扫描声明的根目录，使用 YAML 解析器读取 frontmatter，校验元数据，并拒绝路径穿越、根目录外链接和超限正文。

### Skill Catalog

发布当前技能摘要，按 ID 读取有效正文，隐藏绝对路径，并在重载成功后一次性替换当前索引。

### Plugin Manager

读取插件 manifest 并向 Skill Loader 提供技能根目录。插件技能的加载结果会影响插件健康状态，但插件 API 只公开技能数量，技能明细仍归技能 API。

### Agent Runtime

从 Skill Catalog 获取摘要并加入 system prompt。模型通过只读工具按 ID 获取正文；前端读取和模型读取复用同一个 Catalog。

## 安全约束

- 技能文件必须位于声明根目录内。
- 拒绝路径穿越和链接到根目录外的文件。
- 正文有明确大小上限。
- 技能读取只返回文本，不执行附件或脚本。
- 对外摘要与正文接口不返回文件路径。

## 运行与发布

开发启动流程准备 `src/runtime/skills/` 与 `src/runtime/plugins/`。runnable 构建复制独立技能、插件 manifest、插件技能、MCP 配置和编译产物。两种运行方式使用相同的相对目录、加载规则和重载行为。

## 验收标准

- Wazuh 与 Shuffle 插件技能均能从插件来源识别。
- 新增或修改独立技能后，手动重载即可发现并读取。
- 纯技能插件和多 MCP server 插件可完整加载。
- system prompt 只包含摘要，不包含正文。
- 单个技能失败不影响其他技能或插件服务。
- 类型检查、后端测试、插件测试、前端测试和 runnable 构建通过。
